============================================================
ADB 设备指令台（ADB Device Commander）— 使用说明
============================================================

【一句话】
把本文件夹整体拷贝到任意 Windows 电脑，双击「ADB设备指令台.exe」即可运行，
无需安装 Python。


------------------------------------------------------------
一、使用前准备
------------------------------------------------------------
0. 运行环境自动检查（Web 版每次启动都会做）：
   - 程序启动时会自动检查两件事：WebView2 Runtime 版本、pywebview 依赖；
   - 任一不满足会弹出中文提示窗口并停止启动，照着提示处理即可，无需懂技术细节：
     · WebView2 Runtime：若报「未安装 / 版本过旧」，请到微软官网
       https://developer.microsoft.com/microsoft-edge/webview2/ 下载安装包，
       以【管理员身份】运行安装（需 121 及以上版本；较新 Win10/11 一般已自带，
       仅极旧版本或未安装才需处理），装完重开本程序即可；
     · pywebview：若报「依赖缺失」，在命令行进入程序目录执行 `pip install -r requirements.txt`；
   - adb 缺失【不再阻断启动】：程序会以「未配置 adb」状态进入界面，在「关于」页填入
     adb.exe 所在目录并保存后即生效（设备列表刷新后即恢复）；你无需提前安装 adb 也能先
     打开程序看界面。
1. 安卓设备已开启「USB 调试」（在「开发者选项」里打开）。
2. 电脑已能执行 adb 命令（可选，adb 缺失也能先打开程序看界面）：
   - 推荐把 adb 所在目录加入系统 PATH；
   - 或在程序「关于」页填写 adb.exe 所在的目录并点「保存」，立即注入环境生效。
3. 用数据线连接设备，并在设备屏幕上点「允许 USB 调试」。

（提示：上述检查只会拦截无法运行的硬性缺失；能通过预检即代表环境就绪，
  其它连接/使用问题请参看对应章节。）


------------------------------------------------------------
二、界面总览
------------------------------------------------------------
程序分三块：
  - 左侧「已连接设备」栏：跨页签常驻，勾选要操作的设备（即「受控设备」）；
    标题栏右侧是「无线 / 全选 / 刷新」三个按钮；每张设备卡右侧的 ⓘ 可查看
    该设备的型号 / 系统版本 / 分辨率 / 电量 / 存储 / 内存（详见第三章第 9、10 条）；
    点标题前的 « 按钮可把整栏**收起**成一条 48px 窄轨——上面是 » 展开钮，
    下面是设备数（只留数字）和一条竖排的「已连接设备」铭牌，右侧内容区用满
    宽度；再点 »、或直接点窄轨空白处即**展开**，并恢复收起前调好的栏宽；
    收不收起会记住，下次启动保持原样；
  - 右侧六个页签：设备指令 / 工具 / 性能监控 / Logcat / 文件 / 关于（顶部蓝底白字的就是
    当前页签，一眼可辨）；
  - 顶栏右上角的「状态信息」跑马灯：设备插拔、刷新、执行/停止等程序运行消息
    都在这里滚动显示（与左侧设备栏一样跨页签常驻）。鼠标移上去会暂停滚动，方便
    停下来看清某一行；点它（或顶栏右侧那条）可弹出完整历史，弹窗里能「复制 /
    清空」，也能用鼠标框选其中几行再点复制。关闭弹窗按 `×`、`Esc` 或点弹窗外的
    空白处均可；
  - 屏幕右上角的「Toast」弹出通知：**重要事件的完成提醒**（截图完成、录屏完成、
    Logcat 抓取完毕、打包完成）和**所有错误**都会以弹窗形式出现在右上角，
    几秒后自动消失、也可点它关闭——切到任何页签都不会错过。批量勾选多台设备
    截图时不会逐台刷屏，而是等全部完成后汇总弹一条（几成功/几失败）。

说明：多设备功能（设备指令、工具）对所有「受控设备」广播；Logcat、文件为单设备，
    自动以左侧第一个受控设备为当前目标，随勾选实时联动（单设备页签顶部以蓝色
    「设备: XXXX」指示当前设备）。


------------------------------------------------------------
三、怎么用（指令台）
------------------------------------------------------------
1. 左侧「已连接设备」每 5 秒自动刷新，也可点标题栏的「刷新设备」手动刷新：
   - 点卡片选中 / 取消要下发的设备（可多选）；
   - 只连一台时自动选中；
   - 未授权 / 离线的设备会置灰，无法下发。
   - 若 adb 服务瞬断导致一次空列表，程序会在 0.6 秒后自动重试，不会立刻误报断开。
2. 右侧「设备指令」页签里是按标签分组的快捷指令：
   - 搜索框就在标签栏右侧（始终可见），输入即按指令名称过滤，右侧「清空」按钮复位；
   - 标签胶囊：可多选（或关系），与搜索词叠加为「与关系」；空选 = 不过滤；
   - 「内置」是程序自带的默认命令（独立标签），固定排在所有标签和分组的最下方，
     不打扰你自己的命令；想单独看它就只点这一个标签。内置现有 40 余条通用指令，
     按六类分好并可折叠：连接与投屏 / 显示辅助（指针位置、触摸圆点、系统动画）/
     按键（息屏 / 亮屏 / 返回 / 主页 / 多任务 / 音量 / 静音 / 回桌面 / 亮屏解锁 /
     重启）/ 屏幕状态（充电常亮、锁定竖屏横屏）/ 网络（飞行模式 / WiFi / 移动数据 /
     WLAN IP）/ 应用与信息（Activity / 包名 / 电池 / 存储 / 内存 / logcat）。
     - 点分组标题即折叠 / 展开，折叠状态记在 config.json 的 builtin_folded，
       下次启动照旧；组标题右侧的「全部折叠 / 全部展开」一键处理六组；
     - 搜索框也能搜到分组名：输入「网络」会把网络那一组整段筛出来；
     - **筛选时分组强制展开**，命中项不会藏在折叠块里。
     注：如果你自己的命令文件里已经有同名指令（例如「开启指针位置」），内置那条会
     自动让位不显示——同一条命令不该在界面上出现两次。
3. 点指令即向选中的设备下发；多台设备会逐台执行。
   指令卡可以自己排顺序：**按住卡片约 0.4 秒**（卡片抬起、变亮）后拖动，
   就能在本组内任意换位，松手即保存（记在 config.json 的 cmd_order 里），
   下次启动原样恢复。没拖过的分组仍按点击频次自动排（越常用越靠前），
   顺手拖过的分组则以你排的顺序为准。短按照旧是「执行这条命令」。
4. 自定义命令：底部输入框直接写（和 electerm 终端一样），
   回车或点「执行」下发；adb / scrcpy 会自动按选中设备循环注入 -s。
   「执行」右侧的「保留输入内容」默认勾选：执行后输入框内容保留，方便改几个字重发；
   取消勾选则每次执行后自动清空输入框（适合连发不同命令）。勾选状态会被记住。
5. 「仅输入」模式（兼容 electerm 的 "inputOnly": true）：带此标记的指令（芯片为
   虚线描边）点击后只把命令文本填进上方输入框、不直接执行——改几个字或确认后
   再点「执行」，防止手滑直接跑危险 / 长命令。
   自定义命令芯片右侧有个 ⋮：点上（或鼠标移上去）弹出「复制 / 修改 / 删除」。
   菜单会抬到所有卡片之上，不会被下一条命令压住；命令排在列表最后一两行时，
   菜单自动改成向上弹，不会超出面板被裁。
6. 「停止」：命令卡住（appium、scrcpy、长耗时测试）时用来终止。
   注：指令台只显示你手动输入的命令和其响应；程序运行消息见底部面板，互不混淆。
7. 命令序列里写了 `powershell` / `cmd` / `bash` 这类「进子 shell」的命令时，程序会
   按交互式处理：**只写入、不等返回**，后续命令直接送进这个子 shell，直到遇到
   `exit` 才退出并恢复逐条执行。控制台里会看到这两条状态提示：
     » 已进入交互式 shell：后续命令直接送入该子 shell，输入 exit 可退出并恢复逐条执行
     « 已退出交互式子 shell，恢复逐条执行
   为什么必须这样：这类命令会另起一个进程抢走命令通道，后面每条命令的结束标记
   都被它读走，`exit` 那一行更是把预读的标记一起丢弃再退出——不特殊处理的话，
   整条序列会卡在 `exit` 上再也回不来（表现就是「程序卡死、后续命令点不动」）。
   带一次性参数的写法（`powershell -Command "..."`、`cmd /c dir`、`bash -c "ls"`）
   不算交互式，仍然逐条等返回，能正常判断成败。
8. 兜底超时：单条命令超过 120 秒还没结束会自动终止，控制台提示
   「⏱ 命令执行超过 120 秒，已自动终止」，序列标记为「✗ 执行中断」，不会让整个
   程序一起僵住（没有这层兜底时，任何一条卡住的命令都会把执行通道彻底占住）。
   确实需要跑很久的命令，可在 config.json 里改 cmd_timeout（秒）；设 0 = 不限制
   （慎用：设 0 之后那条命令一旦卡住，就只剩「停止」按钮能救）。


9. 无线调试（Wi-Fi ADB）：车机上不便一直插线时用这个。点设备栏顶部的「无线」：
   - 「设备地址」填设备 IP（只填 192.168.1.23 也行，端口默认 5555），点「连接」；
     整条 `adb connect 192.168.1.23:5555` 粘进去也能识别；
   - 首次必须先插 USB 线：勾选设备 → 点「对勾选设备开启无线调试（5555）」，
     程序会先读出设备自己的 IP，再执行 `adb tcpip 5555`，并把 `IP:5555` 直接填进
     地址框——这之后就可以拔线，点「连接」即可；
   - 「已连接的无线设备」里点「断开」可断开某台；「最近连接」记最近 5 个地址，
     点一下即重连（换了 Wi-Fi / IP 变了就重新走一次「开启无线调试」）；
   - 连不上时看提示即知下一步：拒绝连接 = 还没开 5555；网络不通 = 不在同一网段 /
     开了 AP 隔离；需要授权 = 到设备上点「允许」；地址写错（如 999.1.1.1）会直接
     提示「IP 地址不合法」，不会再让你去查网络。
   注意：电脑与设备要在同一个 Wi-Fi / 网段；公司网络若开了客户端隔离，无线调试连不上。
10. 设备信息：点设备卡片右侧的 ⓘ，弹出的窗口一次列出型号、厂商、Android 版本、
   SDK、系统版本、CPU 架构、分辨率（有覆盖值会一并显示）、屏幕密度、电量与电池
   温度、/data 存储占用、内存、已开机时长。窗口里可「刷新」重新读、「复制」把整份
   信息拷成文本（贴到缺陷单里很方便）。序列号太长被省略号截断时，鼠标悬停卡片可看全。
   容量会按数量级自动换单位（剩余几十 MB 就显示 MB，不会写成「0.0 GB」）；连点两台
   设备的 ⓘ 不会串台（慢的那次回包会被丢弃）；若设备刚掉线导致一项都没读到，窗口里
   会写明「没有读到任何信息」，不会只留一个空白框。


------------------------------------------------------------
四、设备工具（截图 / 录屏 / 应用安装 / 诊断包 / 投屏）
------------------------------------------------------------
在「工具」页签操作，先确认左侧「受控设备」已勾选目标设备：
本页五张卡（设备截图 / 设备录屏 / 应用安装 / 诊断包 / 投屏）**自上而下竖排**，每张卡的
标题栏都可单击收起 / 展开（右侧箭头指示当前状态，收起后只剩一行标题）。常看的展开、
不看的折起来，屏高自己掌控；五张卡的收起状态**各记各的**，互相不牵连。
1. 截图：点「立即截图」，对每台设备各存一张 PNG 到保存目录（文件名带序列号+时间）。
   截图需要设备采集 + 传输 + 落盘，耗时以秒计：点击后按钮会立即禁用（表示"在跑了"，
   也防止连点重复截），完成或失败后自动恢复，期间重复点击不会重复下发；
   截图保存成功会在屏幕右上角弹一条 Toast 通知（切页签也不怕错过）；
   - 想省一步？保持勾选「同步至粘贴板」（默认开启）：截图除了存盘，还会直接写进
     系统剪贴板，马上就能到微信 / QQ / 文档里 Ctrl+V 粘贴；不想同步时取消勾选即可，
     这个开关会被记住。
   - 一次勾选多台设备时不自动写入剪贴板（一次只能放一张图），但每台的图片照常存盘，
     需要粘贴时单独截那台即可。
   - 若状态信息提示「复制到粘贴板失败」，可能是剪贴板正被别的程序短暂占用（程序会
     自动重试几轮，再用系统 PowerShell 兜底重试两轮；兜底时图片字节直接送入
     PowerShell、不经过截图文件，刚落盘的图被安全软件扫描锁定也不会影响）；
     常见于远程桌面会话、安全软件 / 剪贴板工具占用剪贴板——重试一次截图即可；
     无论如何图片都已经保存在保存目录里。
   - 少数车机 / 定制系统截图时会先输出几行自己的提示文字，导致图片文件「开头不是
     PNG」。程序现在会自动跳过这些多余字节再保存，所以图片能正常打开、也能正常
     复制；若仍提示「图片格式无法识别」，说明设备这次返回的根本不是图片，重试一次
     截图即可（提示里会带上文件开头的几个字节，便于反馈问题）。
   - 「打开」用系统文件管理器打开保存目录（保存目录直接在输入框里填 / 改，
     改完会自动同步到工具、Logcat、文件三个页签，并记住到下次启动）。
2. 录屏：
   - 录屏为手动停止：点「停止」即结束并自动收尾、拉回本地（无需设时长）；
   - 录屏只产出画面（MP4）。「同步设备音频」「同步电脑麦克风（本机解说）」两项
     已撤掉：采集链路（设备端 tinycap 探测 / 电脑麦克风混音 / ffmpeg 合成）没真正
     跑通，留着开关只会让人以为录出来的是有声视频，而实际成片一直是无声的。
   - 「同步录制 logcat」「结束录制后自动压缩为 zip」**默认开启**；勾 zip 且录制成功后，
     源文件会被清理（只删本次打包覆盖的文件，不会误删其它文件）；不想要就在录屏卡里
     取消勾选，会记住。
   - 「同步录制 logcat」是**全量**抓取：`adb logcat -b all`（设备上存在的所有缓冲区：
     main / system / events / crash / radio …）＋ **不做级别过滤**（V/D/I/W/E/F 全保留），
     不截断、不过滤、不缺项。录屏配套的日志是事后复现问题的唯一物证——少一条就可能
     正好缺在案发现场上，而录屏一停就再也补不回来，所以这里不再提供任何"精简"选项。
     录制结束后日志（logcat_<序列号>_<时间>.txt）随视频一并打包（若勾了 zip）。
   - 「指针位置」「触摸圆点」默认开启（回顾录像时能直观看到你操作了哪儿）：
     · 指针位置：录屏画面里常驻一个准星，并跟随你的触摸移动（系统设置里的「指针
       位置」，全版本 Android 都支持，不影响录屏本身）；
     · 触摸圆点：触摸时屏幕上画出圆点（系统设置里的「显示触摸操作」）；
       两个开关都是录屏前临时打开、停止录屏时自动恢复你设备原来的设置，
       不会残留在系统里（原本没设过的键会删掉，不会留下多余条目）；
     · 两个开关都会被记住，下次启动沿用；录屏进行中不可改（改了也不生效）。
   - 录屏卡占屏比较高：**单击「设备录屏」标题栏即可收起 / 展开**整块选项（右侧箭头
     指示当前状态，收起后只剩一行标题，把高度让给截图 / 投屏）。收起状态会被记住。
3. 录屏文件可直接播放（已校验文件头，确保能正常识别与收音）。

4. 应用安装（APK）：把本地安装包装到全部受控设备。
   - 点「选择 APK」挑文件（会打开文件对话框，默认定位到程序目录），按钮右侧显示
     文件名与体积；再点「安装到受控设备」。多台设备**各起一个后台安装**，一台失败
     不影响其它台，装完汇总弹一条提示（几成功 / 几失败）；
   - 三个选项：
     · 覆盖安装（-r）：默认开启。反复装同一个包时不用先卸载，也不会清掉应用数据；
     · 允许降级（-d）：默认关闭。设备上是更高版本时，勾上才会装低版本
       （想保留设备上的新版本就别勾，程序会明确告诉你「版本降级」被拒）；
     · 授予全部运行时权限（-g）：默认关闭。装完直接给相机 / 存储 / 定位等权限，
       省掉手动点授权；但会把「权限没申请」这类缺陷一起掩盖掉，验收测试时慎用；
   - 失败码都翻成中文并给出下一步：签名不一致 → 先卸载设备上的旧包；空间不足 →
     清理设备；CPU 架构不匹配 → 换对应架构的包；系统禁止安装 → 打开「USB 安装」；
   - `testOnly` 调试包会自动改用 `-t` 重试一次（CI 出的包常带这个标记），不用手动改参数；
   - 安装是秒级到分钟级的动作，进行中「安装到受控设备」会被禁用；若在上一批还没结束
     时又触发一次，程序会明确提示「上一批安装还没结束，请等它完成后再装」，而不是
     假装开始了却什么都没装；
   - 三个选项都记在 config.json（apk_replace / apk_downgrade / apk_grant），下次启动沿用。

5. 诊断包：出问题之后，一步把现场留全（复现完 bug 发回给开发就用它）。
   - 勾选受控设备后点「收集诊断包」，程序对每台设备各生成一个 zip，存到保存目录；
   - 包里有什么：device.txt（型号 / 厂商 / Android 版本 / ABI / 分辨率 / 密度 /
     电量与温度 / 存储 / 内存 / 开机时长）、props.txt（getprop 全量原样，方便自己 grep）、
     logcat.txt（尾部 N 行，可关掉或选 1000~50000 行）、process.txt（内存 TOP 15 +
     ps 原始表）、apps.txt（第三方应用清单与总数）、anr.txt（前台 Activity +
     最近一次 ANR + /data/anr 与 /data/tombstones 列表）、meta.json（收集时间、
     程序版本、每份文件来自哪条命令、哪些没取到及原因）；
   - 单台约 3~6 秒（logcat 占大头），进行中按钮禁用；再点会提示等当前这批完成；
   - 只读设备状态，不会打断正在跑的 logcat 监控 / 录屏；
   - 某一段读不到（例如 /data/anr 没有权限）不影响整包：那个文件里会写一行中文说明，
     meta.json 里也会标出来，缺哪项一眼能看到；
   - 「含 logcat 尾部」与行数记在 config.json（diag_with_logcat / diag_logcat_lines），
     下次启动沿用。

6. 投屏（需要你电脑上已安装 scrcpy，本程序不内置、不打包它）：
   - 勾选受控设备后点「开启 Scrcpy 投屏」，程序会自动找到你机器上的 scrcpy 并
     `scrcpy -s <序列号>` 起一个投屏窗口；多台受控设备会各开一个窗口。
   - 自动探测顺序：下面「scrcpy 路径」里填的路径 → 系统 PATH → 常见安装目录。
     按钮旁会显示检测结果（版本 + 具体路径），点「重新检测」可重扫；
     没装时会直接在旁边给出安装指引（Windows：winget install Genymobile.scrcpy；
     macOS：brew install scrcpy；或去 github.com/Genymobile/scrcpy 下载解压后
     把解压目录填到「scrcpy 路径」）。
   - 同一条命令连点两次不会开出重复窗口；已在投屏的设备会被跳过并提示。
   - scrcpy 若一闪就退出（设备未授权 / 版本与设备不兼容 / adb 报错），原因会显示在
     按钮右侧的状态文字里，不是"点了没反应"。
   - 关闭本程序时会一并关掉由本程序拉起的投屏窗口；你手动关掉的窗口不受影响。

   没装 scrcpy？用「备用投屏」（同一张卡片的下半部分，按钮「备用投屏（无需 scrcpy）」）。
   它会按下列顺序自动挑一个能用的方式，无需你判断：
   ① screenrecord 管道投屏（推荐档）——把设备画面打成 H.264 流，喂给你电脑上的
      ffplay / mpv / mplayer / vlc 播放器窗口（任装一个即可，都不要额外配置）。
      30~60fps，延迟约 0.2~1 秒，画面在独立窗口里。注意它**只能看、不能用鼠标
      键盘反向操作设备**（这是与 scrcpy 最大的区别）。另外 Android 的 screenrecord
      自带 180 秒上限，到点程序会自动续流，画面卡一下就恢复，不用管。
   ② 低帧率预览（兜底档）——一个播放器都没装时自动退到这里。纯 adb 循环截图，
      画面**直接显示在程序界面里**，1~3fps，适合"确认设备当前在哪个页面"这类
      需求，不适合演示操作过程。这块画面的**右下角有个斜纹手柄**：按住拖动即可
      把它拖大（宽高各自跟随，画面等比缩放、多出来的地方留黑边，不会被拉变形），
      松手即记住大小，下次投屏还是这么大；双击手柄恢复自适应。
   少数 ROM（如部分华为机型）把 screenrecord 命令删掉了，这类设备会自动走 ②。
   可调参数：投屏分辨率（留空 = 按设备分辨率自动缩到长边 1080）、码率（1~50 Mbps，
   卡就调低）、预览帧率（1~10，低帧率预览专用）、播放器路径（留空 = 自动探测）。

7. Logcat 抓取用的是 **「Logcat」页签上方的「落盘抓取」卡片**（不是本页签，
   与下方「实时监控」卡片相互独立、可同时进行），只把日志落盘、更轻量，单台设备）：
   - 点「开始抓取」对当前目标设备抓 logcat 写入本地 txt；随时可「停止」；
   - 「logcat 级别」V/D/I/W/E/F 默认全选（= 全量抓取）：只勾想要的级别即可
     （如只留 I/W/E 看关键日志）；全部取消则只写 adb 自己的标题行（无日志行）；
   - 「结束后打包 zip」（默认开启）：勾选后点「停止抓取」时把这份 txt 打包成 zip
     （源 txt 清理）。抓取过程中不打包、不中断——录多久都不会被自动打断；
   - 缓冲区可选 main/system/events/crash/全部（与实时监控共用，在页签上方设置）；
     文件保存在上方「保存目录」。
   - 适合只想把 logcat 抓下来留存/发给同事、不需要实时监控时使用。


------------------------------------------------------------
五、性能监控（CPU / 内存 / FPS / 卡顿率 / 电量 / 温度）
------------------------------------------------------------
类似 PerfDog 的实时性能面板，指标全部来自设备自带的 /proc 与 dumpsys，
**不注入进程、不装任何东西、不需要 root**，任何开了 USB 调试的设备都能用。

1. 开始监控：在左侧勾选设备后点「开始监控」。
   - 勾选 **1 台** = 常规单设备监控；
   - 勾选 **2 台及以上** = 自动进入「对比模式」：每台一条采样线程，
     同一张图上分色画多条曲线，曲线卡上方出现图例（型号 + 当前读数），
     点图例可切换指标卡与末端读数对应哪台设备。最多同时监控 4 台
     （再多只是在 adb 调用队列里排队，曲线会出现假台阶）。
   - 顶部「应用包名」是一个下拉选择器，默认「跟随前台应用」：每 10 秒重新识别
     一次，中途切换 App 会自动改盯新 App；
   - 点开下拉框可直接从**设备上已安装的应用**里挑（列表由程序调 adb 现读，
     只列第三方应用，勾「含系统应用」才连系统应用一起列），
     搜索框支持模糊匹配：输 chrome、tencent，甚至 comkwo 都能命中；
     选中后全程只盯这个应用，切到桌面也不换；
   - 列表里没有的包名也能用：在搜索框直接把包名敲进去，回车即生效
     （如 com.tencent.kuwo）；
   - 「监控全系统」= 不绑任何应用，只采整机指标（CPU / 内存 / 电量 / 温度）。
     PSS / 帧率 / 卡顿率这三项在这一模式下显示 `--`——它们本来就是「某个应用」
     的指标，硬凑一个「整机帧率」只会让人误读。
   - 应用列表读一次缓存 2 分钟（`pm list packages` 在应用多的机器上要 1~3 秒），
     装 / 卸了应用后点下拉框里的「刷新」即可立刻重读。
2. 七个指标（点任意卡片可切换下方的曲线）：
   - CPU：整机占用率（/proc/stat 差分，0~100%）；
   - 内存占用：整机已用内存 MB（MemTotal - MemAvailable，不是 MemFree，
     按 MemFree 算会把系统缓存当成已用，动辄虚报 90%）；
   - 应用内存 PSS：目标应用的 TOTAL PSS（dumpsys meminfo，Android 上
     唯一不重复计算共享库的口径）；
   - 帧率 FPS：dumpsys gfxinfo 的累计帧数差分 ÷ 采样间隔；
   - 卡顿率 %：本采样窗口内「新增帧里有多少是卡顿帧」（Δ卡顿帧 ÷ Δ总帧）。
     注意这不是 gfxinfo 直接给的累计百分比——累计值挂机两小时后几乎不动，
     看不出「刚才那一下卡」。界面静止、没有新帧时自动退回累计值；
   - 电量 %：dumpsys battery 的 level；
   - 电池温度 ℃：dumpsys battery 的 temperature（原值是十分之一度）。
   卡片上大字是最新值，下面一行是本次采样的「最小 ~ 最大」区间
   （鼠标悬停可看均值 / 峰值 / 谷值 + 采样点数）。
3. 曲线：面积 + 折线 + 纵轴刻度 + 首尾时间，末端标出当前值。
   设备掉线 / 应用重启造成的数据缺口会**断开**而不是连成直线——
   别把「没数据」误读成「运行平稳」。多设备时横轴按**时间**对齐，
   即使某台中途掉线，两条曲线也不会整体错位。
   **鼠标在曲线上移动会出现竖线 + 数值小卡片**：时间点、以及每台设备在该时刻的
   读数与单位（多设备时一行一台，颜色与曲线一致）。指针离采样点超过 26 像素就
   自动收起——空白处不弹卡片，免得挡住本来能看见的曲线。
   **按住左键横拖一段可以框选区间**，松手弹出一张统计卡：该区间的均值 / 最低 /
   P95 / 最高、采样点数，以及配了阈值时「超阈值多少次」。定位一次卡顿用这个比
   逐点读数快得多。双击画布、按 Esc、点卡片右上角 × 都能清除选区；拖得太窄
   （不到 8 像素）按点击处理，不会弹卡。
4. 阈值告警（可自定义，越线即提示）：
   - 内置基线：帧率 < 45 FPS、卡顿率 > 8%、电池温度 > 42℃、CPU > 85%；
   - 越线的指标卡整卡切红（不只数字变色），卡片悬停显示具体规则；
   - 状态栏弹一次提示（8 秒内最多一条，避免抖动曲线刷屏）；
   - 当前指标的曲线会画出红色虚线参考线（Y 轴会主动把阈值纳入可视范围，
     读数远离阈值时也不会把线挤出画面）；
   - 点工具栏的「阈值」可自行修改：四行规则各有一个勾选框与数值框，
     取消勾选 = 不做该项判定，「恢复默认」回到内置基线（改完点保存才生效）；
   - 阈值存在 config.json 的 perf_thresholds 里，形如
       "perf_thresholds": "fps<45,jank>8,temp>42,cpu>85"
     留空 = 用内置基线；写 "off" = 全部关闭；写几段就只判几段
     （覆盖式：删掉一段等于关掉这条，与界面取消勾选完全对应）。
     手改这个文件同样生效，写错时能救的段落照常生效、错的会提示；
   - 判定标准只有后端一份（backend/perf_service.py），界面标红、曲线参考线、
     导出的报告全用同一份，不会出现「报告说没超标、界面标红」的矛盾。
5. 采样间隔：默认 1000ms，可填 200~10000ms。**别贪快**：一次采集本身要
   200~400ms（要跑 4 个 dumpsys），填得比它还小只会排队、曲线反而更糊。
   多设备时每台各跑一条，间隔同样按台计算。
6. 「导出报告」生成文件到「保存目录」，并自动用浏览器打开报告：
   - perf_<序列号>_<时间>.html：设备信息 + 七项指标统计（最小 / 平均 /
     最大 / P95）+ **阈值告警卡片**（超标点 / 占比 / 最差值 / 最长持续 /
     首次出现）+ 七张曲线 + 采样明细表，单文件、无外链，直接发给同事就能看；
   - 报告里的曲线会**给超标时段打红色色带**（单点超标也至少画一个采样间隔
     宽，绝不漏掉「偶发掉一帧」），配红色虚线 + 行尾「≥ 45 FPS」标签与
     卡片右上角的标准说明 —— 不用自己拿读数去和阈值比；
   - perf_<序列号>_<时间>.csv：逐条原始数据（Excel 直接打开不乱码），
     卡顿率同时给「区间值」与「累计值」两列；
   - 多设备时每台各生成一份 HTML + CSV，**再额外出 1 份对比报告**
     perf_compare_<台数>_dev_<时间>.html：对比设备信息表（型号 / 系统 /
     分辨率 / 应用 / 时长 / 样本数）+ 指标对比矩阵（每格「均值 / 峰值」，
     该指标最不理想的一台标红）+ 七张多线图（按时间轴对齐、一设备一色，
     超标点打红点）+ 告警汇总表（哪台在哪项上不达标、占比多少）。
     导出后自动打开的就是这份对比报告。
   停止监控后仍可导出（本次会话的数据会保留到下次「开始监控」）。
7. 关闭程序会自动停止采样；设备拔线 / 掉线时界面会提示「监控已中断」。

说明：本页签是「只看不改」，不做冻结帧 / 卡顿堆栈 / 功耗归因这类深度分析；
需要精确到单帧归因时请用 PerfDog / Systrace。

------------------------------------------------------------
六、Logcat 监控（实时日志 / 过滤 / 异常高亮）
------------------------------------------------------------
在「Logcat」页签，左侧勾选要监控的设备，点「开始监控」（单设备，自动以第一个
受控设备为当前目标，顶部以蓝色「设备: XXXX」指示）：
1. 实时获取当前目标设备的 logcat（顶部「设备: XXXX」即数据来源；切勾选会自动
   换到新的第一个受控设备，监控中的话不打断当前采集）。
2. 过滤（随时调整，不影响已缓冲内容）：
   - 关键字：输入即实时过滤（输入有 250ms 防抖，打字不卡）；
   - 级别 V/D/I/W/E/F：可单独开关，错误行与其堆栈会整体显示或隐藏；
   - 缓冲区：main / system / events / crash / 全部；
   - 「仅显示异常」：一键只看错误与崩溃堆栈。
3. 异常高亮：Java 报错（如 FATAL EXCEPTION、AndroidRuntime、java.lang.*、
   Caused by、ANR、Native crash 等）会以醒目暗红底色标出，便于快速定位。
4. 底部显示「行数 / 异常」计数；支持清空、保存到文件、自动滚动开关。
5. 点「停止监控」结束采集（关闭窗口也会自动停止，不留进程）。


------------------------------------------------------------
七、文件管理（Device Explorer）
------------------------------------------------------------
在「文件」页签（单设备，随左侧「受控设备」自动联动，不需要单独选设备；
顶部以蓝色「设备: XXXX」指示当前浏览设备）：
1. 默认从文件系统根目录 `/` 开始浏览，表格显示 Name / Permissions / Date / Size。
2. 双击目录进入；地址栏可直接输入路径回车跳转；点「↑ 上级」返回上一层。
3. 工具栏/右键可操作：
   - 新建文件夹 / 新建空文件
   - 上传：把电脑文件 push 到当前目录
   - 下载：把选中文件 pull 到电脑本地目录
   - 删除：支持多选，删除前会二次确认
   - 重命名
   - 查看内容：小文件直接展示，大文件先 pull 到临时目录再打开
4. 所有 adb 命令在后台执行，不会卡界面；无权限访问的目录会明确提示错误。


------------------------------------------------------------
八、怎么加 / 改自己的指令
------------------------------------------------------------
启动时会自动扫描程序所在文件夹（运行目录）里的命令合集 json 并合并使用：
  · commands.json        —— 首选文件名；一份有效文件都没有时，程序会自动生成它
  · quick_commands.json  —— 历史文件名，同样会被读取
  · 其它 *.json          —— 只要顶层是数组 / 对象且能解析，也当作命令合集一并载入
多份文件会合并后去重（id 相同、或去掉 [标签] 前缀后同名，视为同一条，保留先出现
的那份；同名不同标签会把标签合并）。直接编辑这些 json（记事本即可），改完重启生效。
格式兼容 electerm 导出（labels / tags / group 都认，command / cmd / script
或纯字符串都行），示例：

  [
    {
      "group": "通用",
      "commands": [
        { "name": "查看设备", "command": "adb devices" },
        { "name": "清日志",   "command": "adb logcat -c" },
        { "name": "设代理", "inputOnly": true,
          "command": "adb shell settings put global http_proxy 1.2.3.4:8080" }
      ]
    }
  ]

其中 "inputOnly": true 即「仅输入」模式：点击该指令只把命令文本填进上方
输入框（不直接执行），确认或改几个字后点「执行」再发；不带这个字段（或 false）
则是点击即直接执行。

解析不出的条目会被跳过，并在程序输出区用 ⚠ 提示，不会导致崩溃。


------------------------------------------------------------
九、配置记忆与防错（config.json）
------------------------------------------------------------
你的各项设置都会自动记住，下次启动原样恢复，不用每次重新勾：
  - 保存目录（工具 / Logcat / 文件三页共享）、adb 目录；
  - 截图「同步至粘贴板」、指令输入框「保留输入内容」、指令台搜索关键字；
  - 左侧「已连接设备」栏的收起 / 展开状态；
  - Logcat：关键字、级别、仅异常、自动滚动、缓冲区、「结束后打包 zip」、抓取级别；
  - 录屏：同步 logcat、打包 zip、指针位置、触摸圆点；
  - 五张工具卡（截图 / 录屏 / 应用安装 / 诊断包 / 投屏）各自的收起状态（shot_collapsed /
    rec_collapsed / apk_collapsed / diag_collapsed / scrcpy_collapsed）；
  - 诊断包：是否含 logcat 尾部、尾部行数（diag_with_logcat / diag_logcat_lines）；
  - 应用安装：覆盖安装 / 允许降级 / 授予全部权限三个开关（apk_replace / apk_downgrade /
    apk_grant）；
  - 无线调试：端口（wifi_port）与最近连接地址（wifi_recent，最多 5 个）；
  - 投屏：scrcpy 的路径、备用投屏的播放器路径 / 分辨率 / 码率 / 预览帧率、
    预览区大小（mirror_view_w / mirror_view_h，0 = 自适应）；
  - 性能监控：应用包名（含「跟随前台 / 全系统 / 某个应用」三种选择）、
    是否在应用列表里带系统应用、采样间隔、图表当前指标；
  - 指令台：搜索关键字、指令卡的拖动排序结果（cmd_order）。
设置保存在 exe 同目录的 config.json 里（可留空 / 删掉该文件恢复默认，删了不碍事）。
程序文件夹里本来就带一份 config.json（打包时生成，列出全部可配置项和默认值），
可以直接用记事本编辑；万一把文件删了，下次启动会按默认值重新生成一份，不碍事。

【换一台电脑继续用同一套设置】
  1. 在「关于」页找到「配置文件」那一行 —— 那里写着 config.json 的完整位置，
     点旁边的「打开目录」就直接跳到它所在的文件夹；
  2. 把 config.json 拷到另一台电脑的同一个程序目录下；
  3. 那边启动后，全部开关、过滤条件、保存路径就都同步过去了。
  注意：保存目录这类是「绝对路径」，源电脑上的路径在新电脑上往往不存在。
  这时程序会**自动改用新电脑的默认目录**（用户目录下的 Pictures\ADB），
  并在状态信息里提示「配置里的保存目录在本机不存在，已改用默认目录」。
  config.json 里记的还是原来那个路径（那台电脑上的正确值）—— 你把它拷回去
  就还是那个目录；想在新电脑上长期用别的目录，在界面上改一次保存目录即可。

防错（你手改 config.json 也不怕）：
  - 写错类型会被自动纠正：比如把开关写成 "true" 字符串、路径写成数字、
    日志级别拼错（不在 V/D/I/W/E/F 里），启动时该项恢复默认值，
    并在状态信息里提示「⚠ 配置已纠正：…」，不会莫名复位也不让错误值生效；
  - 文件损坏 / 保存时用了带 BOM 的 UTF-8 / 只读：静默按默认值启动，程序不会崩；
  - 写入采用临时文件原子替换：中途断电 / 崩溃也不会把配置写成半截文件；
  - 不认识的多余字段会原样保留，不会被抹掉。
  - 旧版本（用 settings.json 存配置的）升级过来会自动迁移一份到 config.json
    并提示一次；旧文件保留不删，你可以留着当备份。


------------------------------------------------------------
十、常见问题
------------------------------------------------------------
Q：提示 more than one device？
A：说明选了多台设备，且命令里写死了某台序列号；去掉写死的 -s 即可。

Q：设备显示「未授权」？
A：在安卓设备屏幕上点「允许 USB 调试」完成授权。

Q：连上设备但列表不显示？
A：检查数据线 / 驱动；点左侧「已连接设备」标题栏的「刷新设备」手动刷新一次。

Q：设备卡片变灰、显示「短暂失联（重连中）」，但线明明插着？
A：这是 adb 服务偶发的一次查询失败（无响应 / 返回空），不是设备真的掉了。程序现在会
   先重试、自动重启 adb 服务，并在约 15 秒宽限期内把卡片置灰保留而不是直接移除，
   期间不可选中以免误发命令；设备回来后勾选与可用状态自动恢复。
   若超过十几秒仍是灰色，再点「刷新设备」，或检查是否有别的 adb 进程在抢占 adb server。

Q：改了命令 json（commands.json / quick_commands.json）没效果？
A：确认 json 和 exe 在同一个文件夹（运行目录），且改完已重启程序。目录里可能有多份
   命令合集会被合并去重；若某条没生效，多半是另一份文件里有同 id / 同名的命令把它
   盖掉了——只保留一份最省心。

Q：录屏卡里以前的「同步设备音频」「同步电脑麦克风」去哪了？
A：撤掉了。这条采集链路的验收始终没过：设备端 tinycap 能不能用因机型而异、
   电脑麦克风只在 Windows 上有、最后还要靠 ffmpeg 合轨——任一环缺失，成片都是
   无声的，而界面上那几个开关却一直勾得上。与其让人以为录到了声音，不如把开关
   去掉，只承诺真能做到的事（画面 + 全量 logcat）。
   需要带声音的录像，请用系统自带录屏 / 第三方录屏工具，或在设备上单独录音。
   （原实现仍留在后端，将来真跑通了再决定要不要把这些开关放回来。）

Q：录屏时执行了 adb root 会怎样？
A：adb root / adb unroot 会重启设备端 adbd，正在运行的 screenrecord 会被
   一起杀掉，视频因此被截断（缺 moov 原子，无法播放、也无法合成音频）。
   为此程序在下发 root 切换前会逐设备自动判断：
     · 设备已在目标状态（已 root 再 root、未 root 再 unroot）→ 直接跳过并
       提示——重复切换除了重启 adbd 没有任何好处，却会白断一次连接；
     · 状态确实要变、但该设备正在录屏 / 录设备音频 / 抓取或监控 logcat →
       一并跳过并弹提示，请先停止这些任务再切换（多设备时只拦有任务的那
       一台，其余设备照常执行）；
     · 命令里仅"提到"adb root（如 git commit -m "adb root 修复"、echo 回显）
       不算切换，不受影响。
   若仍被别的途径中断（例如在另一个终端里手动执行了 root）：程序会检测到
   录屏进程意外结束，自动把界面切回"开始录制"，提示"视频不完整"、跳过音频
   合成、保留源文件；请用完整录制重试。建议：录屏期间不要执行 adb root /
   重启 adbd 等会中断设备端进程的操作。
